# Cloud Serverless Automation Guide: Python vs. Terraform

This guide explains how to automate the continuous execution of security auditing, extraction, and architectural documentation building (**`cloudsec_analysis`**) inside cloud environments.

---

## Python vs. Terraform: What is the Right Tool for Auditing?

### Yes Why PYTHON is Superior for Extraction and Documentation:
1. **Universal API Inspection:** Terraform (*IaC*) is exceptional for **provisioning** and **modifying** resources, but it only knows what exists inside its own `.tfstate` file. **Python** (via official SDKs `google-cloud`, `boto3`, `azure-identity`, `oci`) queries live cloud APIs directly and discovers **100% of existing resources** — including manual, legacy, or third-party workloads.
2. **Markdown/JSON Report Formatting:** Python evaluates compliance rules, calculates security scores, and automatically builds the master documentation book `SECURITY_MIGRATION_DOCUMENTATION.md`.
3. **Zero Risk to Production Infrastructure:** Because Python auditing scripts operate in **Read-Only Mode**, there is zero risk of accidentally deleting or modifying production infrastructure.

### Where TERRAFORM is the Perfect Choice:
- **Terraform is ideal for PROVISIONING THE SERVERLESS AUTOMATION** that runs our Python extractor!
- We use Terraform to create the least-privilege **Security Auditor Service Account**, the **Serverless Job** (*Cloud Run* or *ECS Fargate*), and the **Cron Schedule** (*Cloud Scheduler* or *EventBridge*) in under 1 minute.

## The 3 Easiest Ways to Automate in the Cloud

### 1⃣ The Easiest Option: GitHub Actions CI/CD (Zero Cost & No Infrastructure)
If your repository is hosted on GitHub (`g-jsaccomani/cloudsec_analysis`), the simplest zero-maintenance approach is running via GitHub Actions using **Workload Identity Federation (WIF)** (no static keys required):
- Runs automatically every Monday at 06:00 UTC (or on-demand via `workflow_dispatch`).
- Executes `python3 main.py --live --output-dir ./reports`.
- Automatically commits the updated `reports/` folder back to the repository.
- **Workflow File:** [.github/workflows/security_extraction_cron.yml](file:///Users/jsaccomani/Documents/Jetsky/My%20Projects/cloudsec_analysis/.github/workflows/security_extraction_cron.yml)

### 2⃣ Google Cloud Platform: Google Cloud Run Job + Cloud Scheduler
To execute serverlessly inside GCP:
1. The root `Dockerfile` is built and pushed to Google Artifact Registry.
2. A **Cloud Run Job** executes the container on-demand or on a schedule.
3. A **Cloud Scheduler** job triggers the Cloud Run Job every Monday at midnight via cron `0 0 * * 1`.
4. Extracted JSON and Markdown reports are saved to an encrypted GCS security bucket.
- **Ready-to-Deploy Terraform Module:** See `automation/gcp_cloud_run_job/main.tf` to provision the entire pipeline in GCP with one command:
  ```bash
  cd automation/gcp_cloud_run_job
  terraform init
  terraform apply -var="project_id=YOUR_GCP_PROJECT"
  ```

### 3⃣ Amazon Web Services: AWS ECS Fargate Task + EventBridge Scheduler
To execute serverlessly inside AWS:
1. The Docker container image is published to **Amazon ECR**.
2. An **ECS Fargate Task Definition** runs `python3 main.py` using an **IAM Role (IRSA)** with the `SecurityAudit` AWS-managed policy.
3. An **Amazon EventBridge Scheduler** rule triggers the task recurringly and uploads reports to an encrypted **Amazon S3** bucket.
- **Ready-to-Deploy Terraform Module:** See `automation/aws_ecs_fargate/main.tf` to provision in AWS:
  ```bash
  cd automation/aws_ecs_fargate
  terraform init
  terraform apply -var="aws_region=us-east-1"
  ```

### 4⃣ Microsoft Azure & Oracle Cloud Infrastructure (OCI)
- **Azure:** Use an **Azure Container Apps Job** of type `Schedule` associated with a **User-Assigned Managed Identity** holding the `Security Reader` role.
- **OCI:** Use **OCI Container Instances** triggered by **OCI Events / Scheduler Service** running via **Instance Principals**.
